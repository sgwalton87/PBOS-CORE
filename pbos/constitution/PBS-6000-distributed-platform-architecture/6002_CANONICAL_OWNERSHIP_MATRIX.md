# Purpose

Every distributed platform shall own exactly one constitutional responsibility.

Ownership ambiguity is prohibited.

---

# Ownership Matrix

GitHub

Owns:

- Source Code
- Git History
- Pull Requests
- Actions
- Releases

Supabase

Owns:

- Authentication
- Database
- Storage
- Realtime
- RLS

Google Cloud

Owns:

- OAuth
- Google APIs
- IAM
- Service Accounts

Vercel

Owns:

- Deployment Runtime
- Preview Environments
- Production Hosting

PBOS

Owns:

- Validation
- Certification
- Platform Convergence
- Runtime Intelligence
- Mission Control

---

# Constitutional Rule

No responsibility may possess multiple canonical owners.

Duplicate ownership is prohibited.

---

# Implementation Mapping

Ownership shall map directly to platform runtime implementations.

---

# PBOS Responsibilities

PBOS shall continuously validate canonical ownership.

---

# Definition of Done

Every distributed responsibility has one constitutional owner.

# Canonical Ownership Matrix

| Truth | Owner | PBOS responsibility |
| --- | --- | --- |
| Engineering constitution | PBS / PPS documents | Validate inheritance, dependency, status, and version |
| Repository revision and checks | GitHub | Validate exact commit, branch policy, CI, and release lineage |
| Mission and execution state | PBOS Kernel | Execute, persist telemetry, collect evidence, gate completion |
| Database and application identity | Supabase | Validate schema, migrations, RLS, storage, and auth configuration |
| Cloud identity | Google Cloud | Validate enabled APIs, OAuth configuration, IAM, and service accounts |
| Deployments | Vercel | Validate exact-revision preview/production health and environment parity |
| Public routing | DNS provider | Validate DNS, TLS, redirects, and email records |
| Protected values | Platform-native secret stores | Validate presence, scope, use, and rotation metadata only |
| Product behavior | Running application | Validate browser-visible, durable end-to-end outcomes |

PBOS is the orchestrator and verifier. It does not replace a platform's native truth, copy secret values into evidence, or create an alternate completion authority. Only PBOS Kernel may advance a functional mission to certification readiness.
