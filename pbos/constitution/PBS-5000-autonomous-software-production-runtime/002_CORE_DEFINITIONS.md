# Purpose

Establish the canonical vocabulary governing autonomous software production.

Future PBOS capabilities shall inherit these definitions.

---

# Functional Truth

The verified existence of executable application behavior.

Functional truth is demonstrated through runtime evidence.

Engineering evidence alone is insufficient.

---

# Engineering Evidence

Evidence generated during software development.

Examples include:

- Source code
- Pull requests
- Commits
- Documentation
- Unit tests
- Build output

Engineering evidence supports functional truth.

It does not replace functional truth.

---

# Functional Evidence

Evidence demonstrating working software.

Examples include:

- Browser execution
- User journey completion
- Runtime verification
- API verification
- Database verification
- Accessibility verification
- Acceptance verification

---

# Product Node

A functional capability within the Playbook Platform.

Product Nodes own behavior rather than implementation.

---

# Journey

A complete sequence of user interactions producing a meaningful outcome.

Journeys span multiple Product Nodes.

---

# Autonomous Mission

The smallest independently executable unit of autonomous production work.

Every mission increases functional product capability.

---

# Repository Graph

The canonical model of the engineering repository.

---

# Product Graph

The canonical model of Playbook capabilities.

---

# Journey Graph

The canonical model of executable user workflows.

---

# Acceptance Graph

The canonical model of functional verification requirements.

---

# Definition of Done

Core terminology is standardized.

Future specifications shall not redefine these terms.
