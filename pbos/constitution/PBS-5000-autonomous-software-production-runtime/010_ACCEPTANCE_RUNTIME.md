# Purpose

Functional Acceptance Runtime establishes the constitutional authority governing completion.

Completion shall be determined by executable behavior rather than engineering artifacts.

---

# Constitutional Rule

Engineering evidence supports functional truth.

Engineering evidence shall never replace functional truth.

---

# Acceptance Contracts

Every Product Node shall define an executable acceptance contract.

Acceptance contracts shall verify:

- Runtime behavior
- API behavior
- Database behavior
- User journey completion
- Permissions
- Accessibility
- Evidence

---

# Completion Authority

The Functional Acceptance Runtime becomes the sole authority capable of determining:

- COMPLETE
- FUNCTIONAL
- VALIDATED
- CERTIFIED

No planner, adapter, validator, pull request, test suite, or engineering artifact may independently declare completion.

---

# Acceptance Failure

Acceptance failure shall automatically transition the mission into Autonomous Repair Runtime.

Mission completion is prohibited until acceptance succeeds or a governed stop condition exists.

---

# Definition of Done

PBOS certifies functionality exclusively through executable acceptance evidence.
